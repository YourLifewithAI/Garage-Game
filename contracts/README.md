# The Garage Game's contracts

Run 0 output, 6 October 2026. These schemas are the agreements between the four tracks (Look, Capture, Play, AI companion). Parallel lanes build against them instead of against each other's code. **The integrator owns this directory.** A lane that needs a change proposes it; the integrator applies it here together with every affected example, consumer and test in one commit.

## Validate

```sh
uv venv .venv && uv pip install -r contracts/requirements.txt   # or python -m venv + pip
python contracts/validate.py game/rooms/test_room game/styles/storybook_painterly/v1.json game/rules/storybook_wild/v1.json game/rules/storybook_wild/v2.json
python contracts/validate.py --state path/to/state.json --room path/to/room_dir
python contracts/validate.py --check-style-pins path/to/room_dir
python contracts/validate.py --pin game/styles/storybook_painterly/v1.json
python -m unittest discover -s contracts/tests -v
```

`validate.py` checks the schema and the rules a schema cannot express: unique ids, resolvable references, every referenced file listed with a matching hash and size, self-contained GLB meshes, planar shell polygons wound toward the room interior (floors up, ceilings down, walls toward a point over the floor), unit quaternions, spawns and objects inside the bounds, message size limits, and for room state: entity kinds by namespace, membership in the pinned room, bounds, revision ordering, durable receipts only, the journal (one id per entry, none newer than the store, each list oldest first by revision), the discovered map (entities as their ids say and in the pinned room, each level once, on a support the room has, its bitmap exactly its grid and inside the bounds), and optionally style pins. For island rules it checks that capabilities and categories are unique within a pack, that each param's `default` sits inside its `min` and `max`, that each default radius and duration is at most its maximum, and that a pack lives at its versioned path. For results it checks that `journal.read` answers newest first with one id per entry and `map.find` answers nearest first. For a room with plant copies it reads every table: its header against the set, the tile index, the sort order, every row's numbers (inside the bounds, its tile, its top, its flags and group, a tree's collision), the meshes' triangle counts and pivots, the group numbering and the density limit; for terrain tiles it reads each tiled part's GLB nodes (names, levels, squares, counts). The C# loader (`game/scripts/native/Room/RoomData.cs`) enforces the integrity rules again at load time and fails closed, because rooms in the player's user folder are never run through the Python validator: duplicate keys, path spelling, coordinate bounds after narrowing to float, display-text rules, self-contained GLBs and hashes.

## Schema ids

Every document names its kind in its `schema` field (the link and the wish runner's adapter in `protocol`). Since the rename (decision C of [docs/runs/GARAGE-GAME-RENAME.md](../docs/runs/GARAGE-GAME-RENAME.md), phase 4, 24 October 2026) **writers write `garage_game.<kind>`**; a file written before it says `enfractal.<kind>`. Pinned files keep their bytes, and so their old ids, for as long as they exist: the test room and every installed room, the style presets, the rules packs v1 to v5, the committed characters, the contract examples pinned by hash (the garage room and the room state saved before Run 2). So **readers accept both spellings for good**, not for a transition, and every schema's `schema` field is an `enum` of the two, the new first. A mutable file read with the old id (a team file, a vitals or expertise store, the menu's two files, the wish queue, an island save, the session file) is written back with the new one the next time the game saves it, through its own atomic writer; nothing rewrites a file the player did not touch, and nothing pinned is rewritten. A creation source is pinned by its hash (`source_sha256`, a repair's quote), so it keeps the spelling it was written with; a receipt keeps the result it recorded. Both companion hosts accept a request in either spelling and answer in the new one. A document in neither spelling is refused as an unknown schema.

One table per language holds the pairs, and readers ask it (`is_schema(value, kind)`, in C# `SchemaIds.IsSchema`) instead of comparing strings: `contracts/schema_ids.py` for Python (the validator, the companion, roomscan, the landscape exporter, the character converter, the playtest reader, each loading it by its path), `game/scripts/native/SchemaIds.cs` for C# and `game/scripts/schema_ids.gd` for GDScript. `contracts/tests/test_schema_ids.py` checks that the three agree, that every schema takes exactly both spellings, and that every example is written with the new id but the pinned records.

## Conventions every contract shares

- **Units and axes.** Metres, kilograms, seconds, degrees. Godot axes: +Y up, -Z forward, right-handed, 1 unit = 1 metre. Asset pivots are the bottom centre of the asset's bounds.
- **Pins hash bytes, not meaning.** A room's identity is the SHA-256 of its `room.json` bytes. A preset's identity is the SHA-256 of its file bytes. `room.json` lists every file it references with hash and size, and each `asset.json` lists its own files, so one room pin covers everything below it. Meshes are self-contained `.glb` files: an external buffer or image URI would load bytes no pin covers, so both the validator and the loader refuse it, and the loader builds meshes from the verified bytes with no base path. Pinned JSON is UTF-8 without a byte-order mark and uses LF line endings; `.gitattributes` keeps generated rooms and examples byte-exact on every platform. Never hand-edit a generated room: rerun its builder.
- **Strict JSON.** Duplicate keys, `NaN`, `Infinity` and numbers that overflow are rejected. Integers are written without a fraction (`1`, never `1.0`). Coordinates stay within ±1,000 m. Unknown fields are rejected (`additionalProperties: false`) except inside `extensions`, whose keys start with `x_<lane>_` and which consumers must ignore. The integrator promotes or deletes extension keys; they are for experiments, not for skipping a contract change.
- **Where a room stands.** A room manifest may carry a `site` with three coarse numbers (`latitude_deg` in whole degrees, `neg_z_bearing_deg` for the compass bearing of the room's -Z axis, `solar_noon_h` on a quarter hour). The look works out the sun from it. It never carries a longitude, a place or a finer latitude, and the schema refuses all three, so exported rooms hold no location. A room without a `site` gets the look's fallback and the look says so.
- **Collision-only parts.** A shell part with `"drawn": false` collides but is never rendered, for climbing aids hidden in a tree's leaves or a cap to stand on. Mesh collision is one-sided: a body passes through a face from behind, so a climber can come up through a cap from inside. A part that is neither drawn nor collides is invalid.
- **Paths.** One spelling per file: no `.`, `..` or empty segments. An object's asset is always `objects/<asset_id>/asset.json`.
- **Identifiers.** Lowercase tokens for rooms, assets, presets, spawns and parts. Entity ids are namespaced: `shell:`, `obj:`, `creation:`, `avatar:`, `effect:`, legacy `edit:` and `plant:`, one copy in the manifest's plant copies (`plant:<set>-<row>`, the one namespace with a single spelling per entity: the row in decimal, no leading zeros). Principals are `player:`, `companion:`, `guest:`, `guest_companion:` or `system:` followed by a token. **Host-minted handles are opaque:** an approval's `request_id` and a Fire preview's `preview_id` are 128 bits of hex; a `job_id` is `job-`, a journal entry's id `entry-`, a wish's id `wish:` and an effect's id `effect:`, each followed by 26 characters of lowercase base32 (a-z, 2-7) holding at least 128 random bits from a cryptographic generator. A `preview_id` is the caster's own handle on its own preview of exactly that cast at that room revision, for a few minutes: it is never an approval and grants nothing, and a cast whose place, reach, mode or permission changed since is refused (`revision_conflict`). They are never counters: the base32 alphabet has no 0, 1, 8 or 9, so `goal-000001`, or a count padded in decimal or hexadecimal, cannot match. An id says nothing about how many exist or whose they are, and none is ever shown to the player.
- **Principals never travel in requests.** The trusted adapter assigns the principal; a request that carries one is invalid. Results echo it for audit. This is the rule that keeps a persuaded AI, or later a guest's AI, from claiming the player's authority.
- **Approvals are clicks, not tokens.** A command never carries an approval. When the host wants the player's consent, it holds the exact command and answers `approval_required` with `approval_needed.request_id`, a host-minted 128-bit identifier. The player approves or denies in the game UI. On approval the host commits the held command under its original principal and `action_id`, and the receipt records `approved_by`. Nobody resends anything; the requester polls `approval.status` or `receipt.lookup`. An approval expires, and it lapses if the entities it touches change before the click.
- **World text is untrusted, everywhere.** Every string that names or describes something in the world (display names, categories, labels, notes, room descriptions, sign text) is untrusted data, however it arrived. Single-line fields use `display_text`, which forbids control, line-separator, zero-width, bidirectional-override and other invisible characters (the soft hyphen, the Arabic letter mark, Hangul fillers, variation selectors U+FE00 to U+FE0D, interlinear annotation marks, and plane 14 with its TAG block), so a name cannot fake a new line or hide text. Standard emoji work: VS15 and VS16, the zero-width joiner and the keycap combiner U+20E3 are allowed only where an emoji puts them (a selector right after an emoji or 0-9, # or *, one per base; the joiner between two emoji; the keycap after 0-9, # or *), never alone or in runs, which stops variation-selector smuggling. Tag-sequence flags such as England's stay unsupported, because plane 14 does. A pattern cannot see context, so readers check the markers in code (`contracts/validate.py`, `RoomData.cs`, the companion). Patterns are ECMA-262: `$` matches only at the very end, never before a final newline. Plane 14 needs code in readers that match code points rather than UTF-16 units (`contracts/validate.py` refuses U+E0000 to U+EFFFF, unpaired surrogates and misplaced emoji markers in every string). Free text seen in the world travels in `observe` results as `texts` entries carrying the constant `untrusted: true`, and a picture from the Gubble's eyes (`view.look`) carries `untrusted: true` too: anything legible in it is world text. A wish's words are the player's request to their AI, never rules for it. The companion adapter presents all result data to a model as data, never as instructions; A1's tests prove it.
- **Player-only operations.** `$defs/player_only_ops` lists `protect.unlock`, the player's own settings (`world.set_physics`, `world.set_mode`, `glow.configure`), the player's wishes (`wish.submit`, `wish.stop`, `wishes.read`) and, since the mechanics round, a Fractal's pickup (`item.pickup`), gathering a held log or stone (`item.gather`), a knack (`knack.set`), a receipt's mark (`receipt.mark`) and a Trust reset (`trust.reset`), and since P-Inventory a unit used from the pockets (`inventory.use`) and a thing set down from them (`inventory.drop`): the companion adapter never exposes them and the host refuses them from companion principals (`permission_denied`), never holding them for a click. Every other op, the sandbox verbs, the journal's, the Gubble's magic and nature included, is open to the companion within the rules below.
- **What the companion knows: the team's knowledge.** The player and the companion share one knowledge of the room (the founder, 7 October; `docs/companion/JOURNAL.md`). Only the two avatars' eyes add to it, never the camera and never anything the AI says. In a companion's results `seen: "now"` means in sight of either avatar now, and `seen: "remembered"` means known to the team but out of sight, as last seen, with `last_seen_ago_s`, `last_seen_revision` and the one-bit `may_be_stale`. Anything that changes a thing still needs it in sight of either avatar now. Interim code (Run 1) still fills this from the companion's own eyes only, a subset of the team's, so it conforms.
- **Revisions for a live room.** A command may name `expected_revision` (the whole room, exact) or `expected_entities` (just the entities it cares about, at their revisions); destructive operations must name one of them, `room.undo` must name the room revision (`expected_revision`), and the stops never fail on revisions (see Stops). **`room.undo` takes nature changes back by room revision:** `to_revision` is the room revision just before one of the latest nature changes (Grow, Fire, repairs; the host keeps the last 8), and every change after it must be one of them. The undo is itself a durable room revision. When the latest change is of another kind (building, moving, protecting), nothing can be undone yet: `unsupported_capability`. A revision the island cannot reach back to is `invalid_args`, with the reachable one in `error.allowed`; a revision that is not earlier than now is `invalid_args` too. The Gubble's undo of a change it did not make waits for the player's yes. **Undo exists only in Creative** (the founder, 13 October: what happens in Challenge and Live stays): there `room.undo` is refused for everything, building included, with `unsupported_capability` at `$.op` before any other check (revisions included), and a nature change made there is never undone later in Creative either (`unsupported_capability` at `$.args.to_revision`). A slow companion should use `expected_entities`, so changes elsewhere in the room do not conflict.
- **Receipts.** Commands that change saved state get durable receipts in room state. Commands that change no saved state (goals, stops, effects and Glow's adjustments (`effect.adjust`), grabs, activations, the world's physics while it is not saved, and the player's own settings, `world.set_mode` and `glow.configure`, which the player's profile keeps, never the room, and since the mechanics round `knack.set`, `receipt.mark` and `trust.reset`, which the team file keeps) get transient receipts for the session: the host keeps a bounded number per principal and forgets the oldest first, so a transient command never fails for capacity. `room.checkpoint` and `journal.note` are durable but change no world state, so they do not move the revision; their result data is `checkpoint_revision` and `entry_id`. Putting a thing down (`entity.release`), moving it (`entity.place`) and pushing it (`entity.push`) are durable and move the revision. **The nature changes (`nature.cast`, `nature.trail`, `nature.repair`) and `room.undo` are durable, move the revision and keep their result data in the receipt,** so a replay answers what the first answer said; only a receipt a checkpoint compacted replays without it. A wish (`wish.submit`) is durable in the player's wish journal, not in room state. Receipts at or below a checkpoint may be compacted; `receipt.lookup` then reports `compacted`.
- **Stops.** `goal.stop`, `effect.stop` and the player's `wish.stop` always apply. They are never refused on revisions (their expectations are ignored, malformed ones included), rate limits, capacity or a reused `action_id`: a stop never replays and never conflicts, and a stop under a used `action_id` simply applies again. It never hides a durable receipt under that id: a replay of that command and `receipt.lookup` still answer it.
- **Size limits.** A command or query is at most 65,536 bytes of canonical JSON, a creation source at most 32,768, a result at most 262,144 (a picture from the Gubble's eyes at most 96 KiB, 131,072 characters of base64). Effect parameters are bounded scalars under lowercase names, and names that look like identity or authority are refused.
- **When the host cannot.** `unavailable` means this host cannot do it here at all, whatever the request: a game with no renderer cannot take a picture, and the mock host, which does not simulate nature, cannot cast. It is `retryable` only where waiting helps (a picture not drawn in time).
- **Idempotency.** The fingerprint is the SHA-256 of the canonical command JSON as received from the sender, never of an internal translation. Same principal + same `action_id` + same content returns the original receipt with `replayed: true`. Same `action_id` with different content is refused with `action_id_conflict`. Previews record no receipt. `preview` is part of the content: a retry that only adds `"preview": false` is a different command (`action_id_conflict`), so senders leave it out unless it is true. After an uncertain result, query `receipt.lookup` before retrying.

## The sandbox verbs (Run 2, P3)

Pick up, carry, drop, push, place on a surface with snapping, and stack, all through the command path. Only push is a new op; the rest were already in the contract and keep their meaning. The carry limit is the host's (today the player 0.5 kg and the companion 2 kg); the founder's rule for modes comes later (RUN-1-STATUS.md).

| Verb | Op | Receipt | Who |
|---|---|---|---|
| Pick up | `entity.grab` (`target`, `actor`) | transient | both; a companion only with its own avatar |
| Carry | holding (`held_by`): the thing moves with its holder. The player walks; the companion carries on a goal (`fetch`) | none | both |
| Drop | `entity.release` with no placement: set down where the actor stands, then settles | durable | both; a companion only with its own avatar |
| Place, with snapping | `entity.release` with a placement; with `placement.on` the host snaps it onto that entity's walkable top at `position_m`'s horizontal place. `entity.place` moves a thing without carrying it (the companion's magic, the player's editing hand) | durable | both |
| Stack | the same, with `on` naming another movable thing; the support's own `position_m` centres it there | durable | both |
| Push | `entity.push` (`target`, `distance_m` up to 1 m, optional `toward_m`, `actor`): slid along its surface with collisions, away from the actor or toward the point | durable | both; a companion only with its own avatar |

Refusals: out of reach is `out_of_bounds` (retryable); no room, or a push that is blocked, is `occupied`; something resting on the target is `target_busy`. A goal whose actor finds no way to its target (`come`, `go_to`, `fetch`) fails with **`target_unreachable`**: the target exists and is known, but no route reaches it. That is not `out_of_bounds`, which means outside the room or beyond reach from where the actor stands.

- **None of them is player-only.** Fetch needs the companion to pick up, carry and put down. A companion may never act through the player's avatar (`actor_denied`), and the player may direct the companion's.
- **Fetch** (`goal.set`, `goal: "fetch"`): the companion walks to the target, picks it up with `entity.grab`'s checks and limit, and brings it back to the player, still holding it; its job succeeds then. `entity.release`, from the companion or the player directing it, puts it down. So the goal stays transient and the move that is saved is its own durable command.
- **Holding is not saved.** A carried thing is saved where it was last put down; a session that ends mid-carry leaves it there.
- **A verb's result carries no `data`.** The moved thing is in `affected`; where it came to rest is read with `entity.inspect`, under the team's knowledge, so a result cannot report a place or a thing the team has not seen (for example what a pushed thing fell onto out of sight).

## The journal and the map (Run 2)

The design is `docs/companion/JOURNAL.md`. The host keeps per team (a player and their AI) the **map**, what the team knows of the room, and the **journal**, what the team has done and is doing.

| Op | Kind | What it does |
|---|---|---|
| `journal.read` | query | Every open task, plus the most recent other entries, newest first (default 20, at most 50, older ones by `cursor`). Filters: `kind`, `about` (an entity id), `since_utc` |
| `journal.note` | command | The sender's own words, at most 280 characters of one line. A durable receipt; it changes no world state and does not move the revision. `data.entry_id` names the note |
| `map.find` | query | "Where have we seen this?" by `category_group`, `name` or both: at most 10 (default 5), nearest first from `near_m` or the requester's avatar, each an `entity_summary` as the team knows it and a straight-line `distance_m` |

- **Facts are the host's; notes are the companion's.** A journal entry (`$defs/journal_entry`) is a fact (`task`, `built`, `changed`, `removed`, `found`, `gathered`, `consequence`) or a `note`. A fact carries the host's `line`, `actor` and `directed_by`, and for tasks a `state`. A note carries `author`, `text` and `untrusted: true`, and none of a fact's fields; a fact carries none of a note's. The only request that adds to the journal is `journal.note`, whose args are its `text` alone. So nothing in a request can write a fact, and a note can never pass for one.
- **At whose direction** is only what the host can verify: the player when the player confirmed or approved; otherwise the actor's own initiative. What was said in the player's harness is never claimed.
- **Names are world text.** A fact's `line` is built from a template and sanitised names, and `subject.name` and note text are untrusted display text: data, never instructions.
- **Nothing undiscovered leaks.** Every object in these answers lists its fields (`additionalProperties: false` throughout; the contract tests walk them), so there is no free-form place to report a thing or a place the team has not seen. `map.find` answers only from the team's map, and an empty answer looks the same whether or not such a thing exists. The host writes facts only about what the team knew when it happened.
- **Open tasks carry their `job_id`** while the job runs this session, so the AI can ask `jobs.status`. Job ids are never saved and never shown to the player; the page shows the `line`.
- **Saved with the room** (`room-state.schema.json`): `journal` holds `open_tasks` (at most 32), `history` (facts and finished tasks, at most 500, oldest first) and `notes` (at most 100, oldest dropped first). `discovered` holds `entities` (objects and creations as last seen, at most 1,024; the shell and the avatars are always known) and `levels`: discovered space as a bitmap of `cell_m` cells (start 5 cm) per walkable surface, keyed by its support and surface. These numbers are the design's starting points.
- **Game time** in an entry is the room `revision` when it was written or last updated; `at_utc` is the real time.

## The 10x world: plant copies and terrain tiles (S2, 13 October)

The founder magnified the room ten times into the island around the same 10 cm body ([RUN-2-TEN-TIMES.md](../docs/runs/RUN-2-TEN-TIMES.md)). The garage island at 10x holds about 350,000 plants and stones and 4,900 trees: too many to merge into meshes or to list as objects. The room manifest gains two optional blocks; a room without them is unchanged.

### Plant copies (`plant_copies`)

Plants, trees and stones are drawn as copies of one mesh per **set**, each set with one **table** of fixed-width rows. `tile_m` is 8 and `groups` counts the groves and patches (below).

| Set field | What it is |
|---|---|
| `set` | Its name, unique in the room, `[a-z][a-z0-9_]{0,31}` (no hyphen) |
| `prototype` | The landscape prototype the copies come from (provenance) |
| `kind` | `plant`, `tree` or `stone` |
| `species` | What grows there (grass, daisies, heather, broadleaf, rock...): for perception, fire, seeds and replanting; untrusted like every name |
| `collides` | `none` (plants), `tree_climb` (trees: the row's trunk, pole and caps) or `solid` (stones: the convex hull of the level-0 mesh, transformed) |
| `fuel_class` | `none` (stones), `grass`, `herb`, `shrub` (plants), `broadleaf`, `conifer` (trees). Fire's numbers per class are the host's and the island rules', never the room's |
| `seeds` | Whether copies set seed: their seeds can be gathered and a burnt copy is replanted and regrows. Never for stones |
| `mesh`, `triangle_count`, `lods` | The copy at full detail (self-contained GLB, the prototype's own frame, pivot at the bottom centre, unscaled), then up to 3 lighter meshes for distance, each lighter than the one before. The game picks by distance; the data names no ranges |
| `table` | The rows (`.bin`), listed in `files` with hash and size like every file |
| `cap_slots` | Trees only: cap slots per row (1 to 8) |
| `tiles`, `count` | Entries in the table's tile index, and rows |

**Identity.** Row `n` of set `s` is the entity `plant:s-n` (`common.schema.json` `plant_id`). The rows are pinned by the manifest's hash and saves are pinned to the manifest, so the id is stable for the room. Fire, seeds, replanting and the AI's perception address single copies by it (the fire rebuild). What happens to a copy (burnt, regrowing, replanted) is room state, never the manifest. Saved entities stay `obj:`, `creation:` and `avatar:`; no manifest object rests on a copy (copies burn); copies count toward no other cap.

**Groups.** `group` puts a copy in a grove or patch that the generator placed together, numbered 1 to `groups` across all sets, every number used; 0 is no group. Perception can say "a grove of 40" instead of listing each tree.

**The table** (`.bin`), little-endian, every field 4 bytes:

| Bytes | Field |
|---|---|
| 0 to 7 | magic `EFPLANTS` |
| 8 to 39 | eight u32: format version (1), kind (0 plant, 1 tree, 2 stone), row bytes, row count, tile count, cap slots (0 unless a tree), tile_m (8), reserved (0). The header is 40 bytes |
| then | the tile index: one 16-byte entry per non-empty 8 m tile, `i32 tx, i32 tz, u32 first, u32 count` |
| then | the rows, `count` of them, each `row bytes` long |

The file is exactly 40 + 16 × tiles + row bytes × rows long, and the header agrees with the set (`kind`, `cap_slots`, `count`, `tiles`).

A row is 56 bytes for plants and stones:

| Offset | Field | Meaning |
|---|---|---|
| 0 | f32 x, y, z | The pivot (bottom centre) in room metres, inside the bounds |
| 12 | f32 yaw_deg | About +Y, -180 to 180 (Godot's rotation.y: 90 turns +X toward -Z) |
| 16 | f32 scale x, y, z | Of the mesh, each in (0, 100]; the copy is position + yaw × (scale × mesh) |
| 28 | f32 tint r, g, b | 0 to 1, multiplying the mesh's colours as the exporter's merged meshes do |
| 40 | f32 top_m | The copy's top in room metres: y + the mesh's height × scale y (within 1 mm) |
| 44 | u32 flags | Bit 0 `submerged` (its base is under water: fire does not reach it there). Every other bit is 0; readers ignore bits they do not know |
| 48 | u32 group | Its grove or patch, or 0 |
| 52 | u32 variant_seed | A number for the copy's variety (sway, colour shift, regrowth variant), fixed with its row |

A tree's row is 84 + 32 × cap_slots bytes: the 56 above, then its climbing collision as `pipeline/landscape/export/trees.py` fits it to the ground, in room metres:

| Offset | Field | Meaning |
|---|---|---|
| 56 | f32 x, z | The trunk's and pole's axis |
| 64 | f32 trunk_radius_m | The trunk at its base (the trunk runs from the row's y to trunk_top_m) |
| 68 | f32 pole_radius_m | The trunk at its top, and the hidden pole above it |
| 72 | f32 trunk_top_m, pole_top_m | The pole runs from the trunk's top to pole_top_m, at most the highest cap's top: a climber comes up through a cap |
| 80 | u32 cap_count | Caps used, 1 to cap_slots; the unused slots are zero bytes |
| 84 + 32k | f32 x, z, rim_half_x_m, rim_half_z_m, rim_m, top_m, top_half_x_m, top_half_z_m | Cap k: a collar from its rim ellipse (half-sizes along x and z, at rim_m) up to a flat perch ellipse (at top_m, no wider than the rim) |

The drawn tree never collides; these numbers do. The game builds its own shapes from them (S6: primitives), so a body can climb the trunk and the pole and stand on each perch.

**Order.** Rows are sorted by tile (tx, then tz, with tx = floor(x / 8) and tz = floor(z / 8) of the stored float32 values), then by x, then by z; the tile index lists the non-empty tiles in that order, each `first` the previous entry's `first + count`, from 0. Copies of one set at exactly the same x and z keep the exporter's order.

**Limits.** At most 64 sets, 16,777,216 rows a set, 8 cap slots, and 256 copies per square metre of the bounds' footprint, all sets together: a limit that grows with the land rather than with a scale factor (today about 60 per square metre at 1x and at 10x). A table is at most 256 MiB like every file.

### Terrain tiles (`terrain_tiles`)

The land is cut into 16 m tiles (`tile_m`, 16) with levels of distance detail (`levels`, finest first, each coarser: today 0.1 m with finer detail where a body meets the land, 0.4 m and 1.6 m). `parts` lists the tiled shell parts and how many tiles each holds. Inside each such part's GLB every node is a tile node named `tile_<tx>_<tz>_lod<level>` (tx = floor(x / 16), tz = floor(z / 16), in decimal with `-` before a negative and no leading zeros; level indexes `levels`): a root of the scene with a mesh, no transform and no children, its positions in room metres inside its tile's square. Every tile of a part has every level.

- **Level 0 is the ground.** A colliding part collides through level 0 only; the walk checks hold on it. The game draws one level per tile, choosing by distance. Neighbouring tiles of one level meet without cracks; hiding the seam where levels meet is the exporter's (S4, S5), and the loader assumes only level 0 for walking.
- **Unchanged:** a tiled part is still one shell part, with its id, role and material; supports still name it (`shell:terrain_grass`); the 128-part cap stands. Parts not listed (water, scenery, collision-only aids) keep one mesh drawn whole.

### Observe on the island

`observe` answers everything in the actor's line of sight on the whole island when `radius_m` is omitted: line of sight is the real limit. A given `radius_m` narrows it, at most 150 m (more than the 10x garage island's farthest corner, about 100 m). Both hosts and the companion's tool description say the same; the companion's alignment tests check the kernel's `ObserveRadiusMaxM` and entity id pattern against these schemas.

### Play distances (S8)

- **`entities.list`'s `filter.near.radius_m` is at most 150 m,** as far as `observe`'s radius (it was 50 m, seven times today's islands). The kernel's `NearRadiusMaxM`, the schema and the mock agree; the companion's alignment test checks them.
- **The Gubble catches up.** Following or coming to the player, farther than 25 m from them and out of their view, the Gubble reappears beside them, out of view too, instead of travelling the rest (the founder's decision 4 of the 10x plan; never in a fetch, into a wall or into water). It did not do that itself, so its AI is told: a fixed-form notice (`$defs/catch_up_notice`: `caught_up`, where it was, where it reappeared, the straight-line `distance_m` and when; no one's words) rides once on the companion's next result, of any kind, in `notices`, beside any `consequence_notice`. Its goal goes on. The mock host does not simulate bodies and sends none.

### What the exporter (S5) and the loader (S6) build against this

- **S5 writes** the sets (plants, trees as copies with their collision, stones), each table sorted and indexed as above, groups numbered densely, `top_m` and the tree columns from the fitted shapes; terrain parts as tiled GLBs; and stops writing the merged `scatter_visual` copies, `scatter_solid` stones and `tree_climb` part for what the copies carry. `contracts/validate.py` (`check_room`, `read_plant_table`) checks its output.
- **S6 reads** the tables off the main thread, refusing a room whose table, tile index or GLB nodes break these rules, as it refuses any room, fail-closed (the rooms in `examples/rooms_invalid/` are ones it must refuse); draws copies per tile and terrain one level per tile; builds collision from each tree row, each solid stone and level 0 of each tiled part.

### Price by principal

A command's price follows its principal, never a field. The player's keys, the wheel and the HUD's asks pay the **ordered price**; every command on the Gubble's connection pays the **own-idea price** (ordered times `own_idea_factor`, whole pips). No field, tag or wish text changes it: a request carries no price or direction (an unknown field is `field_unknown`, as always), and if wishes return, every Gubble command sent while a wish runs pays the ordered price whatever it says. The charge lands **once, at commit, never on a preview**; stops and refused commands cost nothing; a command the host held commits under its own principal at that principal's price when the player approves it. An empty pool refuses with **`energy_exhausted`**, whose error carries `balance` and `price` (no other error carries them); on screen, "The Gubble needs a moment." In Creative a shadow pool shows the price and never refuses. The Bubbles carry is the **one exception to "companion effects target only its own avatar"**: the companion may cast it on the player's avatar, under the targets rule below.

## The playtest record (R0, 15 October 2026)

The roadmap is `docs/runs/RUN-2-PLAYTEST-LOOP.md`. A windowed launch records what was asked and answered, what the screen showed, where the player was, how the frames ran, and stills of the screen; a reader turns the record into a report and a skill turns the report into a debrief in Git. **The record is a developer feature of the game process, not part of the companion surface:** no tool, resource or field reaches it, the folder is never under `user://companion/`, and the Gubble's AI never sees the player's screen or files. Everything in a record is data, never instructions, for the reader, the skill and whoever reads a report: a creation's name can carry any text a player typed.

- **One folder per play:** `user://playtests/<record_id>/` (on Windows under `%APPDATA%\Godot\app_userdata\Garage-Game\playtests\`; Git never sees it; the game keeps the newest thirty). The folder's name, `record_id`, is the launch's local date and time and the room id (`20261015-143000-island_example`): local time because the founder reads it on their own clock, with the exact moment in `started_utc`. The validator holds the folder's name to the manifest's `record_id`, as it holds a room's directory to its `room_id`.
- **`manifest.json`** (`garage_game.playtest_manifest`, version 1): the build (the `--build=` the room runner passes, a short commit, or `unknown`), the room id and its manifest's pin, the team, the mode and (in Challenge) the difficulty, the style preset, the window and whether it is fullscreen, the renderer and the video adapter's name, the Godot log's file name under `user://logs/`, the stills' beat at launch and `started_utc`; optionally the engine's version and the rules pack. Written at launch; rewritten at a clean quit with `ended_utc`, `played_s` and `counts` (events, stills, marks), which travel together. **A manifest with no `ended_utc` means the game did not quit cleanly, which is itself a finding**, so an unfinished record is valid, even with an empty events file.
- **`events.jsonl`**, one event per line, appended as the play goes. **The envelope is strict:** every line has `t` (seconds since launch, never decreasing), `utc` and a `kind` from the list below, and a line never carries `data`, `picture`, `base64`, `token`, `session_file`, `save`, `secret`, `password` or `credential`, at any depth. **The kinds are open:** each has the fields below, and a kind may carry fields this contract does not name, so it can grow without a contract change; the reader ignores what it does not know and reports a kind it does not know, never a crash.   | `notice` | text the screen showed, at the moment it changed | `channel` (`hud` line, `gubble` bubble, `status` cue, `refusal`), `text` (empty when cleared); optionally `reason`, `code`, `action_id` |
  | `body` | the breadcrumb, every two seconds | `position_m`, `height_m`, `state` (standing, walking, running, swimming, diving, climbing, falling, carried, fading_home), `view` (eye, shoulder, diorama, isometric), `gubble` (`distance_m`, `link`: offline, listening, planning, acting, waiting); optionally `level`, `mode`, `hearts`, `bar_m`, `pips`, `holding` |
  | `frame` | every five seconds | `window_s`, `mean_ms`, `longest_ms`, `position_m`; optionally `physics_ms`, `draw_calls`, `video_mb`, `static_mb`, `objects` |
  | `still` | a picture was taken | `file` (`0001-steady.jpg`, `0003-mark-1.jpg`, `0006-keep-1.jpg`, `0002-refusal.jpg`; numbered in order of taking, named for the reason), `why` (steady, mark, keep, refusal, home, mode, quit); optionally `view`, `position_m`, `width`, `height` |
  | `mark` | F9 "something's off" (`flag` off) or F8 "keep this" (`flag` keep) | `number` (each flag counts from 1), `flag`, `still` (the one it took, numbered as the mark is) |
  | `stills_rate` | F7 or F6 moved the beat | `beat_s` (0 off, 1, 3, 10, 30); optionally `was_s` |
  | `session` | the companion link started or ended | `state`; optionally `principal`, `sessions` |
  | `quit` | the last line of a clean quit | `played_s`, `events`, `stills`, `marks`, equal to the manifest's `counts` and to the file |

- **`stills/`**: the pictures, never in Git and never read by the validator (a missing still is the reader's finding). The steady beat is at half the width and half the height; marks, keeps and refusals are full size.
- **What `validate.py` checks** (`check_playtest`, run on a folder: `python contracts/validate.py contracts/examples/playtests/20261015-143000-island_example`): the manifest; every line as strict JSON and as an event (a truncated last line, CR LF, a byte-order mark, a blank line and a line past its limit are each named); `t` and `utc` never running backwards and never before `started_utc`; at most one `ready` and the quit last; the stills numbered in order, named for their reason and never taken twice; a mark's still the one it took; and at a clean quit the manifest's counts, the quit line's totals and the file agreeing. The example play and sixteen broken records are under `examples/playtests/` and `examples/playtests_invalid/`.

## Versioning and change protocol

Each document carries `schema` and an integer `version`. Within a version, the integrator may add optional fields. A change that would make an existing valid document invalid, or change the meaning of a field, bumps `version` and comes with a migration note in this file and a converter where saved data exists. A lane requesting a change writes the proposed diff and its reason in its run report; it does not edit `contracts/` itself.

## Styles are versioned files

A preset lives at `game/styles/<preset_id>/v<preset_version>.json`. While its status is `seed` or `draft` the Look lane edits it in place and nothing may pin it. Once a version is `candidate` or `approved`, or anything pins it, its file never changes; a change is a new version file, and old versions stay so old saves keep their look. The game resolves a pin by id and version and verifies its hash; a pin that does not verify falls back to the default look with a visible notice (`RoomWorld.StyleNote`), never silently. `style.set` names an id and version; the host pins the file's hash in room state.

## Island rules are versioned files

An island's rules are data (`garage_game.island_rules`): the abilities it grants, each carried out by one engine primitive, with its bounds, who may cast it (`cast_by`), what it may target (`self`, the effect follows the Gubble, which carries every ability out; `point`, the effect at `area.center_m` within `reach_m` of the Gubble) and its safety tier (`auto`, `auto_undo`, `preview_commit`, `keyed_yes`: LIVE-VOICE.md's T0 to T3).

- **The layers, each narrowing the one above.** The engine fixes each primitive's outer limits; they live in the schema as one `if`/`then` per primitive, and an island's pack sets each ability's bounds inside them. Every primitive takes `intensity` only, from 0.05 to 2.0 (1 is the look's standard), and has a radius of at most 3 m:

  | Primitive | Category | What it is | Reach | Duration | Active |
  |---|---|---|---|---|---|
  | `light.emit` | `light` | a real light, following the Gubble or floating at a spot (Glow) | 5 m | 600 s | 8 |
  | `particles.float` | `float` | one player-sized bubble cast at a spot, the place deciding what it is (a carry round the player, a boat on water, a bubble to walk into), led by the Gubble (Bubbles) | 5 m | 120 s | 4 (one at a time) |
  | `particles.burst` | `burst` | a burst of sparks with a brief flash of real light, over the Gubble or above a spot after a rocket trail (Fireworks) | 8 m | 10 s | 4 |
  | `growth.seed` | `growth` | flowers on the island's ground (Bloom and its flower trail, retired by decision 52: a host reads a pack's `growth.seed` ability as Grow); radius at most 0.6 m | 5 m | 600 s | 1 |
  | `growth.grow` | `growth` | the island's own plants grown bigger, a share of their natural size a cast (the intensity, 0.05 to 1.0), up to the host's cap (Grow); radius at most 1.0 m; cast with `nature.cast` at a point; no duration | 5 m | 600 s | 1 |
  | `element.ignite` | `fire` | fire on the island's ground, spreading with dryness and wind, put out by rain, leaving ash that regrows (Fire); radius at most 1.5 m; cast with `nature.cast` after a preview | 5 m | 60 s | 1 |

  Particles are cosmetic: nothing collides with them, and a bubble pops as a look effect when an avatar or the land touches it. A stream costs particles every frame, so its duration is short of a light's; a rocket carries further than a light or a stream. A burst's flash is one light: it counts toward the look's light budget and, while it lasts, toward `LightLevelAt`, and with at most one light per effect the host's cap of 8 effects per room still bounds the lights. Widening a limit later invalidates no pack, so the limits start narrow. A command must sit inside the ability's bounds, and the host fills omitted params from the defaults. `capabilities.list` reports the pack's bounds and which command casts each ability; `effect.start`, `effect.stop` and `capabilities.list` carry abilities unchanged. The nature primitives are not effects: they are room state the host simulates, cast with `nature.cast`, which reads the pack's intensity (its default, inside the outer 0.05 to 2.0) and its radius, duration and reach.
- **Narrow only.** A pack can never widen a primitive's limits: a value past them fails the schema, and the host loads the pack fail-closed, as it loads rooms.
- **Pins.** A pack lives at `game/rules/<rules_id>/v<rules_version>.json` and the game loads it as `res://rules/<rules_id>/v<rules_version>.json`. Like a preset, a `seed` or `draft` version may change in place; a `candidate`, `approved` or pinned version never changes, and a change is a new version file (the contract tests keep locked versions in `LOCKED_RULES` by SHA-256).
- **A newer primitive is a newer pack version.** A host loads a pack fail-closed, so it refuses a whole pack that names a primitive it does not carry out. A pack that adds one is therefore a new version, and a host moves to it once it carries out every primitive the pack names. `storybook_wild` v1 holds Glow alone; v2 (draft, 10 October) adds Bubbles (`bubbles`, `particles.float`) and Fireworks (`fireworks`, `particles.burst`), with Glow unchanged; v3 (draft) raises Glow's ceiling to the five lights the team can earn; v4 (draft, 11 October) adds Bloom (`bloom`, `growth.seed`) and Fire (`fire`, `element.ignite`). The kernel host (`RoomWorld.DefaultRulesVersion`) and the mock host (`DEFAULT_RULES_VERSION`) load v4; the mock lists Bloom and Fire and answers their casts `unavailable`. v5 (draft, 14 October) adds the mechanics round's blocks to v4's abilities ("The mechanics round" above); the mock already reads its prices, and both hosts move to it with M1. Since 16 October (decision 52) v5 grants Grow (`grow`, `growth.grow`, 4 pips ordered, 2 as the Gubble's idea) in Bloom's place, and both hosts read a pinned pack's Bloom (`growth.seed`) as Grow.
- **Wheel slots are the HUD's rule.** The HUD places abilities on its wheel by category, with slots fixed by the engine: light 1, growth 2, float 3, burst 4, build 5, fire 6 (decision 77: key 6 and the ninth wedge, just after Fireworks; also in the Magic panel, M). The contract keeps `category` an open token, unique within a pack.

## Shipping a room that uses GLB meshes

Captured rooms load at runtime from `user://rooms/`, where the raw `.glb` bytes the loader hashes are on disk. A room shipped inside the game (`res://rooms/`) with GLB meshes needs Godot to export those raw bytes: mark each room `.glb` with the `keep` importer and commit its `.import` sidecar, then add that room to the release probe. The test room uses primitives only, so nothing ships this way yet.
